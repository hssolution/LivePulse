# 화면 디자인 편집기 재설계 — 설계 문서

- 작성일: 2026-05-28
- 대상: `src/pages/partner/SessionDetail.jsx`의 `DesignSection` (세션 상세 > "화면 디자인" 탭)
- 상태: 설계 확정 (구현 계획은 writing-plans로 이어짐)

## 1. 배경 / 문제 정의

파트너가 세션을 만들 때 "화면 디자인" 단계에서 참가/Q&A/투표 화면용 템플릿을 고르고 이미지를 올린다. 현재 구현의 문제:

1. **템플릿 선택이 블라인드** — 드롭다운 3개로 이름만 보고 고른다. 어떻게 생겼는지 모름.
2. **미리보기 충실도 갭** — 우측 인앱 미리보기는 `DynamicTemplateRenderer`(필드 기반 범용 렌더)인데, 실제 청중 화면은 `JoinSession`/`LiveSession`의 하드코딩 switch 렌더 함수다. **두 코드 경로가 달라 인앱 미리보기 ≠ 실제 청중 화면**이 될 수 있다. → 파트너가 "유저 화면이 어떻게 되는지 모르겠다"고 느낀 근본 원인.
3. **에셋 편집 UX가 정적** — `<input type=file>` + URL 입력 + 작은 썸네일. 드래그앤드롭/검증/비율 안내 없음.
4. **좌측 폼이 길다** — 모든 설정이 한 컬럼에 세로로 쌓여 스크롤이 길고, 저장 버튼이 우상단에만 있어 폼 끝에서 다시 올라가야 한다.

## 2. 스코프 (확정)

**파트너 편집기 UX만 재설계.** DB 스키마(`session_templates`/`session_template_fields`/`session_assets`)와 청중 렌더 코드(`JoinSession`/`LiveSession`/`BroadcastQnA`의 switch 렌더 함수)는 **건드리지 않는다.** 단, iframe 임베드 미리보기를 위해 `/live`·`/broadcast`에 `?embed=true` 모드 추가는 허용(렌더 로직 자체는 불변, 크롬 UI만 숨김).

명시적으로 **이번 범위 밖** (다음 페이즈 후보):
- 템플릿 모델 재설계(테마/씬/컴포넌트 분리)
- 브랜드 컬러 토큰, 섹션 on/off, 섹션 순서 재배열
- 썸네일 갤러리(자동 렌더 or 수동 업로드)
- 청중 여정 리허설(타임라인 자동 재생)

## 3. 핵심 결정 요약

| 영역 | 결정 |
|---|---|
| 스코프 | 파트너 편집기 UX만 |
| 우측 미리보기 | 3탭(참가/Q&A/투표) + 기기 토글(모바일/태블릿/데스크탑) |
| 미리보기 충실도 | **iframe으로 실제 라우트 임베드** (C-1) + 저장 시 자동 새로고침 |
| 편집 깊이 | 에셋 UX 강화만 (필드 타입 불변) |
| 템플릿 선택 | 드롭다운 유지 + 슬롯별 🔍 전체화면 미리보기 버튼 |
| 좌측 패널 | 섹션 아코디언 + 상태 배지 |
| Light/Dark 토글 | **폐기** (청중 화면에 light/dark 테마 시스템 없음) |

## 4. 레이아웃

기존 리사이즈 분할 유지(`leftWidth`). 좌측 아코디언 편집기 / 우측 미리보기.

```
┌─ 화면 디자인 ────────────────────────────────────┬──────────────────────────────┐
│ 좌측: 아코디언 편집기 (width%)                    │ 우측: 미리보기                │
│ ▼ ① 템플릿              ✓ 3 선택 완료              │ [참가][Q&A][투표]   기기 토글 │
│    참가 화면 [학술 심포지엄 ▾] 🔍                  │ ┌──────────────────────────┐ │
│    Q&A 화면  [기본 송출    ▾] 🔍                  │ │  선택 탭 = 실제 라우트     │ │
│    투표 화면  [참가 따름    ▾] 🔍                  │ │  iframe (기기 프레임)      │ │
│ ▶ ② 이미지 / 에셋       ⚠ 필수 1건 누락           │ └──────────────────────────┘ │
│ ▶ ③ 링크 / 기타 설정                              │ 🔗 실제 화면 새 창으로 열기   │
│ [💾 저장] (하단 sticky, 변경 시 ● 표시)            │                              │
└────────────────────────────────────────────────────┴──────────────────────────────┘
```

## 5. 컴포넌트별 설계

### 5.1 좌측 아코디언 편집기

3개 접이식 섹션. 각 헤더에 자동 상태 배지(`✓ 완료` / `⚠ 필수 N건 누락`)를 계산해 표시.

- **① 템플릿** — 참가/Q&A/투표 드롭다운 3개(기존 유지). 각 옆 🔍 버튼 → 해당 화면 실제 미리보기 새 창. Q&A/투표는 "참가 템플릿 따름" 기본값.
- **② 이미지 / 에셋** — 필드별 카드 (5.2 참조). 에셋 UX 강화 핵심.
- **③ 링크 / 기타 설정** — image 외 필드(url/text/boolean), `open_new_tab` 토글 등.

저장 버튼을 패널 **하단 sticky**로 이동(현재 우상단). 미저장 변경 시 점(●) 인디케이터.

### 5.2 에셋 카드 UX 강화

- **드래그앤드롭 존** — 카드에 파일 드롭 + 클릭 업로드 유지.
- **권장 사이즈 시각화** — `max_width` 텍스트 → 권장 비율 박스 + 업로드 이미지 실제 px 표시.
- **검증 경고(비차단)** — 권장 폭 초과/미달, 비정상 비율 시 노란 경고. 업로드 자체는 막지 않음.
- **썸네일 확대** — 호버 시 크게.
- **URL ↔ 파일 일원화** — 한 카드 안 탭 전환("파일 업로드 / URL").

> 제약: `session_template_fields`에는 `max_width`만 있고 권장 높이/비율은 DB에 없음. 스코프 A(DB 불변) 유지 위해 비율 경고는 **클라이언트 추정**(필드 키 키워드: `*_banner`→가로형, `logo`→정사각 등)으로 처리.

### 5.3 우측 미리보기 (3탭, iframe)

- 탭: **참가 / Q&A / 투표**. 각 탭 = 해당 실제 라우트를 iframe으로 기기 프레임 안에 스케일 렌더.
  - 참가 → `/join/:code?preview=true&embed=true`
  - Q&A → `/broadcast/:code`(Q&A 송출) — `qna_template` 반영
  - 투표 → 투표 송출 화면 — `poll_template` 반영
- 기기 토글(모바일/태블릿/데스크탑) — 기존 `previewDevice` 재활용, iframe 래퍼 크기로 적용.
- **저장 시 자동 새로고침** — iframe은 저장된 데이터를 읽으므로, 저장 성공 콜백에서 iframe `key`/`src`를 갱신해 최신 저장본 반영.
- `DynamicTemplateRenderer`는 이 화면에서 더 이상 1차 미리보기로 쓰지 않음(충실도 갭 제거). 필요 시 보조로만.

### 5.4 🔍 풀스크린 미리보기

슬롯별 🔍 버튼 → 실제 라우트 새 창 열기(기존 링크 인프라 재활용). 인앱 탭은 빠른 확인, 🔍는 전체화면 정밀 확인.

## 6. 데이터 흐름

1. 파트너가 드롭다운에서 템플릿 선택 → `formData.template_id` 등 갱신(기존).
2. 에셋 카드에서 파일/URL 입력 → `previewData`/`assets` 갱신(기존).
3. 저장 → 기존 RPC(`sp_*`)로 `sessions` + `session_assets` 저장(기존 로직 불변).
4. 저장 성공 → 우측 iframe 강제 리로드 → 청중이 실제로 볼 화면 = 미리보기.

## 7. 미해결 / 구현 시 확인할 점

- `/live`·`/broadcast`의 `?embed=true` 지원 추가 필요(JoinSession은 이미 있음). 임베드 시 헤더/네비 등 크롬 UI만 숨기고 렌더 본체는 불변.
- 투표 "송출 화면" 전용 라우트가 별도인지 `/broadcast`가 Q&A·투표를 함께 다루는지 확인.
- iframe 미저장 반영 불가 → "저장해야 미리보기 갱신" 안내 문구 필요.
- 기기 프레임 스케일링 방식(transform scale vs 고정 width) 확정.

## 8. 테스트 관점

- 참가/Q&A/투표 3탭 각각 iframe이 올바른 라우트를 로드하는가.
- 저장 후 iframe이 새 에셋을 반영하는가.
- 아코디언 상태 배지(필수 누락 감지)가 정확한가.
- 드래그앤드롭 업로드 + URL 입력 양쪽 경로 동작.
- 기기 토글 3종 전환.
- 보기 모드(관리자 view-as)에서도 정상 동작(데이터는 대상 파트너 기준).
